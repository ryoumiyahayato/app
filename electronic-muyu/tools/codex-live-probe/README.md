# Codex C1-LIVE Probe Harness

This directory is a validation-only harness. It is **not** the product Collector and must not be moved or renamed to `codex-collector/` before the C2 gate passes.

## Safety boundary

The probe may send only:

- `initialize`
- `initialized`
- `account/rateLimits/read`
- `account/usage/read`

It blocks `thread/start`, `turn/start`, `account/rateLimitResetCredit/consume`, and every other non-allow-listed RPC. It never reads or asks for OpenAI passwords, cookies, access/refresh tokens, `auth.json`, API keys, or relay secrets.

Rollouts are processed as:

```text
read -> parse -> allow-list projection -> discard original content
```

The report/checkpoint may retain only quota/token metadata, timestamps, ordinals, safe model metadata when explicitly attributable, source version, and truncated SHA-256 identifiers. Raw rollout rows, prompts, assistant content, source code, tool output, email, credentials, and full filesystem paths are never retained.

`occurredAt` remains `null` for token events unless the source explicitly declares token occurrence time. Rollout envelope timestamps are `persistedAt`, not model-occurrence timestamps.

## Windows target-computer run

From `electronic-muyu/`:

```powershell
powershell ./tools/codex-live-probe/run.ps1
```

Expected local outputs:

```text
tools/codex-live-probe/C1_LIVE_RESULT.json
tools/codex-live-probe/C1_LIVE_RESULT.md
```

The probe uses the target computer's existing Codex login through the local `codex app-server`; it does not request credentials. If `codex` is not on `PATH`, set `CODEX_BIN` to the local executable before running.

Zstandard validation requires one of: Python `compression.zstd`, the `zstandard` Python package, or a `zstd` executable on `PATH`. If none is available, `JSONL.ZST` remains failed and C2 is not ready.

## Gate semantics

C2 Collector MVP is eligible only when all of the following are PASS:

```text
G1 QUOTA READ
G2 TOKEN LEDGER
MODEL-FREE MONITORING
SENSITIVE DATA LEAK CHECK
JSONL / JSONL.ZST parser tests
replay / restart dedup tests
```

`G3 RESET OBSERVATION` may remain PARTIAL. Natural weekly reset, rate-limit-exhausted read, and reset-credit presence are non-blocking observations and must not be fabricated.

An independently spawned read-only app-server may not receive token notifications generated by a different Codex process. Therefore rollout observation alone never upgrades `LIVE TOKEN EVENT` or `LIVE ↔ ROLLOUT MATCH` to PASS. If live notification evidence is unavailable, the report correctly remains `LIVE USER ACCOUNT VALIDATION: PENDING` and `READY FOR C2 COLLECTOR MVP: NO`.
